# ADR-0120 — Office import is ONLYOFFICE's x2t, contained, and ADR-0092's deferral ends

- **Status:** Accepted
- **Date:** 2026-09-29
- **Supersedes:** [ADR-0092](0092-office-import-is-deferred-because-libreoffices-pipe-cannot-be-contained.md)'s deferral,
  by its own third reopening route — *"a converter for these formats that runs inside the container as it stands"*.
- **Amends:** `docs/ARCHITECTURE.md` §3's *Office document → PDF* row, and the amendment log.
- **Keeps:** [ADR-0063](0063-an-office-file-is-converted-by-a-pinned-libreoffice-in-a-contained-process.md)'s converter
  seam and its Decision 2 — a fixed input name, a tree this repository provisioned, never the machine's own copy.
- **Decided by:** the owner's afternoon list of 28 September, item 8, and the owner's choice on 2026-09-29 of Document
  Builder's archive over Desktop Editors'.

## The measurement (item 8a), 2026-09-29

**Artefact.** `ONLYOFFICE/DocumentBuilder` release v9.4.0 (published 2026-05-20), asset
`onlyoffice-documentbuilder-windows-x64.zip`, 81,782,152 bytes, SHA-256 `5b509f6d…e488e2` as GitHub's release API
gives it and as the downloaded file hashed. `x2t.exe` is 39,539,696 bytes in a 180 MB tree.

**Instrument.** `scripts/research/x2tContained.mjs`: `libreofficeContained.mjs`' shape — the same session directory
pair and `win32HostSurface` with a program kind of `converter`, a params file naming the bundled fonts and a temporary
directory inside the pair, the tree granted read-and-execute to the container profile alone, and an uncontained cell
first as the control.

| input | uncontained | contained |
|---|---|---|
| `.docx` | `%PDF-1.7`, 71,821 B, the probe text read back by Poppler | identical |
| `.xlsx` (hand-written) | `%PDF-1.7`, 35,001 B, the cells read back | identical |
| `.pptx` | `%PDF-1.7`, 36,498 B, the probe text read back | identical |

**Control.** With the tree's grant removed, the contained `.docx` cell wrote nothing while its uncontained twin
converted — so the contained cells were contained. Each conversion took 4.4–7.0 s on a machine running a sweep.

LibreOffice's wall was a fixed-name pipe created before any conversion. `x2t.exe` carries no pipe or mutex name among
its strings; the evidence is not that absence but that it converts inside the container.

**Fonts, measured the same night.** Without a font cache x2t refuses (exit 80, `DoctRenderer: <error code="open"/>`).
Document Builder writes the cache on start, and by default indexes this machine's fonts — 466 under `C:\Windows\Fonts`
and 26 in the user's profile. Started with `--fonts-system=false` it indexes exactly the tree's own 11 font files
(Carlito, Caladea, Asana, OpenSymbol and `ASC.ttf`), and a conversion with that cache embeds Carlito and reads back
whole. **The cache records absolute paths**, so it belongs to where the tree sits.

**Not measured, and owed by the build's live run:** the job object's one-process limit and the Low integrity level —
the research surface applied the container alone, and the product's `containedProgram` applies all three.

## Decision

1. **Office import converts `.docx`, `.xlsx` and `.pptx` to PDF with x2t**, in a contained process through
   `containedProgram`: one conversion per process, input and output in a granted session pair under fixed names, the
   PDF opened by the one open route.
2. **The tree is provisioned from the pinned archive and pinned file by file** (`pinnedTree.mjs`), extracting what x2t
   loads. Document Builder's own scripting (`docbuilder.*`) is not shipped and not used to convert.
3. **Fonts are ONLYOFFICE's bundled set**, and the font cache is generated by provisioning with `--fonts-system=false`
   for the tree's own location, so a conversion reads nothing of the machine's fonts. Where the packaged tree lives is
   packaging's to settle with the cache's absolute paths; the build records how.
4. **Licences:** ONLYOFFICE core is AGPL-3.0, compatible with Monstera's AGPL-3.0-or-later; `NOTICE` carries it with a
   source offer, and each bundled font's licence (the SIL Open Font License, 1.1 for Carlito, Caladea and Asana, 1.0
   for OpenSymbol).

## Rejected

- **LibreOffice** — ADR-0092's pipe, unchanged.
- **Desktop Editors' archive** — 598,575,987 bytes for the same `x2t`.
- **Document Builder's scripting to convert** — it prints *"license is invalid"*, inserted *"Unregistered Version"*
  into a slide it generated, and wrote a workbook with no sheet; `x2t` alone did neither.
- **A font cache over the machine's fonts** — a container cannot read a user's profile, and a conversion that depended
  on what one machine has installed would differ from the next.
- **An online converter** — ADR-0063's rejection stands.

## Correction, 2026-09-29 — what the build found

Appended by the build (item 8c), and each paragraph answers a sentence above.

**The cache no longer records absolute paths, so Decision 3's packaging question is closed.** Document Builder writes
each font path three times — the list in `AllFonts.js`, one record per face in `font_selection.bin`, and that file's
faces again, base64-encoded, inside `AllFonts.js` — and provisioning rewrites all three to name the fonts relative to
the tree. The seam starts every converter in its executable's directory, so the relative names resolve wherever the
tree lives. Two stagings at paths of different lengths produced byte-identical pins; `proof:onlyofficefontcache`
holds the rewrite byte-exact or refused. The first rewrite left each record's length and the base64 copy stale, and
still converted: **x2t converts from a cache whose paths do not resolve**, embedding a different Carlito program
(30,632 bytes in a 31,812-byte PDF, against 30,836 in 53,300). Which file that came from was not established — this
machine's `C:\Windows\Fonts` holds a byte-identical Carlito, readable from the container.

**The job object and the Low integrity level are measured.** `scripts/research/officeLive.mjs` runs the product code
— `createOfficePlatform`, `createOfficeSource`, and so `createContainedHost`, which reads back job membership,
integrity and limits before it resumes the process — on a generated `.docx`, `.xlsx` and `.pptx`: each converted in
1.1–1.2 s with a job peak of 330–352 MiB, and each sentence read back. A 16 MiB process limit refused the same
`.docx`, so the limit reaches x2t. A generated deck with no theme stopped x2t's script (exit 80); every deck an
application writes carries one, and the fixture now does.

**The subset.** Every DLL in the archive is in x2t's import table (each removal: exit `0xC0000135`), so all twenty
ship; Document Builder's scripting, the dictionaries, the headers, `doctrenderer.lib` and the empty templates do not.

**The licences are wider than "AGPL-3.0 and SIL OFL".** Core's `LICENSE` closes with Additional Terms under Section 7
(retain notices, mark a modified version, show legal notices in an interactive interface, no trademark licence), and
core's `3DPARTY.md` at the shipped build 9.4.0.130 declares 26 third-party components; `NOTICE` carries all of them,
and says which of them are compiled into the Windows build was not established one by one.
