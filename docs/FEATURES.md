# Feature catalog and status

The complete scope, known before the first line of architecture code. This is
the **destination**, reached through the staged releases in
`docs/ARCHITECTURE.md` and `BUILD-PROMPT.md` Part G — beginning with a
deliberately smaller 1.0.

**Part H requires the row for a feature to be updated in the same commit that
finishes it.** A row that says `done` for a feature whose control renders but
does nothing is a defect in this file as much as in the code — see the
wired-tools rule.

| Zoom: fit-width / fit-page / presets / ± / Ctrl+scroll. **Landed 2026-09-02.** `ZOOM_STEPS` is the ladder; the steps clamp at each end rather than wrapping. Registered as commands, so every surface is a projection of one entry. **The three viewport-relative modes followed the same day.** **A zoom is a MODE, not a number** (`zoom.ts`): `±` produces a scale, a fit produces itself and has no number until the scroller has measured its own box and a page's. It measures with a `ResizeObserver`, not a window listener: the box that matters changes for reasons the window never sees. | Two-tier zoom: instant CSS stretch + 150 ms debounced true re-render. **Landed 2026-09-02.** Two numbers hold the two tiers: `zoom` moves the moment a reader asks and the browser stretches the bitmap already on screen; `renderZoom` follows once the gesture settles and the page is rasterised at exactly `devicePixelRatio × renderZoom` — never supersampled and downscaled, which E1 bans as a default. **A bitmap stores the scale it was drawn at**, so its CSS size at any later zoom is a ratio rather than a guess. `devicePixelRatio` is read at the point of use, not captured at mount. **THE PRINCIPLE THAT ORDERS ALL FOUR, and it predicts more than it summarises: only kernel-enforced mechanisms contain native code.** A job object, an integrity level, a token, an AppContainer — the kernel checks these on every access, whoever makes it. Node's permission model is enforced inside Node's own filesystem bindings, so it constrains JavaScript and nothing else. This is why QQ-1 leaves (a) and (b) **untouched** while it removes (d)'s only candidate: integrity levels and job objects are kernel objects and bind the MuPDF shim exactly as they bind the host's JavaScript. Do not read "the containment conclusions were about the wrong adversary" as applying to all four — it applies to the one mechanism enforced in userland. It also settles (c) without a further measurement: no Node-level mechanism will ever deliver it, since the permission model has no network dimension and would be enforced in the same place if it grew one. And it generalises past this flag — of any proposed containment mechanism, ask **who enforces it** before asking what it denies.
