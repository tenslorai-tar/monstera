# Feature catalog and status

The complete scope, known before the first line of architecture code. This is
the **destination**, reached through the staged releases in
`docs/ARCHITECTURE.md` and `BUILD-PROMPT.md` Part G — beginning with a
deliberately smaller 1.0.

**Part H requires the row for a feature to be updated in the same commit that
finishes it.** A row that says `done` for a feature whose control renders but
does nothing is a defect in this file as much as in the code — see the
wired-tools rule.

| ADR-0009 §8 — the **engine seam**. Both writer shapes live in the type: `Apply<W, K>` is conditional on the declared writer, so a live-session writer mutates in place and returns void while a byte-image writer consumes an image and produces one. **Exactly one adapter** implements it — MuPDF, live-session — and the byte-image side deliberately has nothing behind it. Its control is a type-level fixture in `proof:contract` that builds a byte-image writer and a byte-image `Apply` **with no type assertion**; modelling the seam on live-session ops alone turns it red. | **`DocumentService` holds the canonical bytes** ([ADR-0009](DECISIONS/0009-document-identity-and-the-command-log.md) §8, [ADR-0007](DECISIONS/0007-memory-budgets-and-the-document-size-ceiling.md), [ADR-0021](DECISIONS/0021-the-canonical-image-is-retained.md)). The seam **enabled** this and did not satisfy it: `open` takes bytes and `serialise` returns them, so no engine is forced to become authoritative — but the record held none, so killing an engine host lost everything since the last save. *How many are resident:* exactly one image per open document, its lifetime the record's, **sized rather than assumed** — `perf:gate` reports `main` at 1.00× of file size holding one and 2.00× holding two, breaching ADR-0007's 1.5×, which is that instrument's resolution test run before the decision rather than after. **Measured twice, and the second is the evidence:** `roleMain.mjs` is a MODEL that never constructs a `DocumentService`, so its figures are arithmetic about bytes, while `roleMainService.mjs` opens through the real service with the production reader and reads **1.00× and 1.03×**. Capacity is checked from `stat` **before** the read and again from the bytes read, because those are two observations of a file anything may write between. **And a killed host recovers, asserted against a RUNNING process, 2026-08-31.** `proof:hostrecovery` starts a real contained host, kills it, waits for a **different** process to appear as a child with nothing asked of the shell — a retry succeeding would prove something weaker and would race the lane — and then sends one command, which succeeds. Its control is the second death, which must **poison** rather than rebuild for ever: a shell that never poisoned would pass every other case, and one that poisoned immediately would pass that one. **It found the defect it was written for**, and the mechanism is in the JOURNAL: the ending inherited the async context of whoever built the connection, the host is built lazily inside the first document's lane, and the reopen was therefore refused as reentry — so the shell rebuilt the process and left the document sessionless. | **done** |
